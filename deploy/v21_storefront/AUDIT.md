# V21 임시 쇼핑몰 점검 — 2026-10-05

현재 서버는 사용자가 확인한 정식 오픈 전 임시 서버입니다. 이 변경은 해당 서버의 기능 개선이며 정식 오픈이나 결제 계약을 진행하지 않습니다.

## 반영 사항

- 메인 기본 HTML 및 로그인 상태 조회 후 문구를 `로그인/회원가입`으로 통일합니다. 로그인한 회원에게는 기존처럼 `마이페이지`를 표시합니다.
- 모바일 전체메뉴도 같은 문구를 사용합니다. 로그인 페이지 제목을 변경하고 로그인/회원가입 영역으로 이동하는 버튼, 비밀번호 길이 안내, 지속 표시되는 오류 메시지를 추가합니다.
- 로그인/회원가입 요청이 진행 중이면 다시 제출하지 않습니다. 로그인 후 돌아갈 주소는 같은 쇼핑몰로 제한합니다.
- 비회원 주문서에서 로그인/회원가입으로 이동하고 주문서로 돌아올 수 있습니다. 장바구니를 그대로 사용합니다.
- 결제 키/SDK 또는 무통장 계좌정보가 준비되지 않은 결제수단을 비활성화합니다. 사용 가능한 결제수단이 하나도 없으면 `결제 준비 중`으로 표시합니다. 외부 계약·계좌정보를 임의로 등록하지 않습니다.
- 주문 요청 중 같은 페이지에서 반복 클릭하여 요청이 겹치는 것을 막습니다. 이는 서버 차원의 멱등성 구현이나 결제 재시도 설계를 대체하지 않습니다.
- 쿠폰 최소 주문 조건과 정률 할인은 상품금액 기준으로 계산하고, 최종 할인 상한은 서버와 동일하게 상품금액+배송비로 계산합니다. 서버의 기존 금액 계산을 바꾸지 않습니다.
- 제주/도서산간 배송비가 총 배송비에 포함된 금액이라는 점을 명시합니다.
- 품절/판매중지 상품 구매 버튼을 비활성화하고, 수량의 정수·재고 검증이 실패하거나 장바구니 저장에 실패하면 즉시 구매 화면으로 이동하지 않습니다.

## 확인한 범위

- 임시 서버 브라우저: 메인, 회원 진입 화면, 상품 상세, 장바구니 담기/이동, 주문서, 고객게시판, 상담 진입.
- 임시 서버 공개 API: 정상 응답, 결제/입금계좌 설정 여부만 확인. 키나 계좌값은 기록하지 않았습니다.
- 점검 시 공개 상품 4개는 대표 이미지와 상세 이미지가 등록되지 않은 임시 데이터였습니다. 운영 데이터 유실로 판단하지 않습니다.
- 로컬 DOM 시나리오: 로그인 전후 버튼, 회원가입 이동, 안전한 복귀 주소, 요청 중 중복 제출, 이용 가능한 결제수단 조합, 쿠폰 종류·최소 주문금액·최대 할인, 수량/품절/판매중지.
- 모바일 장바구니·저장 배송지와 반품/교환 화면의 기존 회귀 테스트.
- 별도 임시 DB에서 앱 기동, 고객 페이지 및 로그인 보호 API 점검.
- 실제 임시 서버에 주문·회원·문의·리뷰를 생성하거나 실제 결제를 실행하지 않았습니다. 관리자 로그인 뒤의 전체 업무를 수동 검증한 것은 아닙니다.

## 정식 오픈 전 다음 작업

1. 실제 판매 상품의 대표/상세 이미지, 용량·구성 수량, 옵션 가격, 배송/반품비를 등록하고 메인 배너를 실제 제품 중심으로 교체합니다.
2. 하단에 확정된 운영 사업자와 고객센터 정보를 표시하고 이용약관·개인정보 안내·배송/반품 안내를 마련합니다. 확정되지 않은 회사 정보나 정책을 임의로 넣지 않았습니다.
3. 이메일 인증을 이용한 비밀번호 찾기/재설정 기능을 추가합니다. 현재 로그인 페이지에는 해당 진입 기능이 없습니다.
4. 결제 계약/테스트 키 준비 후 PC·모바일에서 승인, 실패, 취소·부분 취소, 반품 입고 후 환불을 검증합니다. 결제 중단 뒤 재시도, 쿠폰/포인트로 0원이 되는 주문, 동시 주문 재고 처리는 별도 통합 검증이 필요합니다.
5. 주문·회원 DB 및 업로드 이미지의 영구 저장과 백업/복구를 확인합니다. 현재 코드의 기본 DB 및 업로드 경로는 로컬이므로 정식 서버에서 영구 저장소 설정 확인이 필요합니다. 실제 서버 환경변수의 민감한 값은 조회하지 않았습니다.
6. 네이버 상품 EP 기능은 기존 코드에 있습니다. 실제 상품정보 등록 뒤 EP 검수와 가격비교 입점을 준비합니다. 이번에 네이버 입점을 신청하지 않았습니다.

## 실행

Render의 기존 조립 명령은 마지막에 `deploy/v21_patch.py`를 실행합니다. 이 파일에서 `v21_storefront_patch.py`를 기존 패치들 뒤에 실행합니다. 생성된 app/static 파일 자체를 GitHub 원본으로 덮어쓰지 않습니다.

테스트는 조립된 디렉터리에서 실행합니다.

```sh
NODE_PATH=/path/to/test-only/node_modules node deploy/v21_storefront/test_storefront.cjs
NODE_PATH=/path/to/test-only/node_modules node deploy/v21_mobile/test_mobile.cjs
cp deploy/v21_ui/test_mypage_returns.cjs deploy/v21_ui/test_return_request.cjs .
NODE_PATH=/path/to/test-only/node_modules node test_mypage_returns.cjs
NODE_PATH=/path/to/test-only/node_modules node test_return_request.cjs
```
